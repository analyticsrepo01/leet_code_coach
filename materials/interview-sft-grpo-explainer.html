CRAM: SFT and GRPO, in plain English (interview prep, quants related)

All numbers come from the repo. [NOT FOUND] = not in the repo. [CHECK] = the sources disagree or it's unclear. The main sources are listed at the end of each section.

1. One-paragraph summary

AI agents work with a limited "desk": the text window the model can see. On long tasks the desk overflows and old notes get thrown away, sometimes the one ID the agent needed. CRAM tried to teach a small model (Gemma 4-E4B, 4 billion parameters) to tidy its own desk. It labels pieces of text [KEEP], [COMPRESS], [EVICT] (throw away) or [REFOCUS] (back to the goal), and it never drops protected items marked <shield>. I used two methods:

  • SFT (supervised fine-tuning) shows the model worked examples.
  • GRPO (a reinforcement-learning method) lets the model try answers and get scored.

I needed both because GRPO alone could not reward a habit the model never showed.

2. SFT: how I did it

  • What it is. The teacher shows the student finished, correct answers, and the student learns to copy that style. Technically: train the model to predict each word of a gold answer. Loss is counted only on the answer, not the question.
  • Why CRAM needed it. Without help the model almost never wrote a directive: 0% in the baseline run, 0.3% in the Guardian run (100 steps each).
  • The 156 examples.
    • One per task in the 156-task dataset (14 domains), written by a Claude model through the API.
    • The model name is [CHECK]: the script's docstring says claude-opus-5, but the code calls claude-opus-4-8.
    • All 156 use only [KEEP]. There are no COMPRESS, EVICT or REFOCUS examples.
  • One real example (fleet/jira_github_sync_01, trimmed):

3. GRPO: how I did it

  • What it is.
    • For each task, the model writes several answers (4).
    • Each answer is scored, and its "advantage" is its score minus the group's average.
    • Answers above average are made more likely, answers below less likely. No separate critic model is needed.
  • Why not PPO: PPO needs a value (critic) network and importance clipping. GRPO uses the group average as the baseline, so it is simpler and fits on one GPU (KL via disable_adapter(), no second model copy).
  • Why not DPO: no written rationale in the repo [NOT FOUND]. A fact: the repo has a deterministic reward, but no preference pairs, which DPO needs.
  • Settings:
setting value
group size G 4
grad accumulation 4 (16 rollouts per update)
KL β 0.04
clip ε none: plain policy gradient, no PPO ratio clip; gradient-norm clip 1.0
learning rate 5e-5; 2e-5 for GRPO after SFT
steps 100; 200 for curriculum and GRPO after SFT
temperature 0.9 (first runs), 1.1 (later), 1.3 (one ablation)
max new tokens 300
  • Reward: the parts are summed with no extra weights. The directive bonus is set per run.
    • Task 0 to +1: share of the task's "must-do" keywords found in the answer.
    • Directive +1, +3 or +5: any [KEEP]/[COMPRESS]/[EVICT]/[REFOCUS] in the answer.
    • Shield: +1 if every <shield> item appears; −2 for each one dropped.
    • Thrift (length penalty) 0 to −1: −0.5 × (words over 150) / 100, capped at 2.
    • Also format: +0.1 each for <think> and <answer>, −0.2 if both are missing.
  • The exploration wall.
    • GRPO only compares answers it actually produced.
    • If none of the 4 answers contains a directive, every answer gets the same directive score. The difference is zero, so nothing pushes the model toward directives.
    • That's why raising the bonus from +1 to +3 to +5 changed nothing: 1.3% usage at +3 and +5, 0% in the last 20 steps at +3.
    • Telling the model it must use a directive made directives appear from step 2 (7.0% usage).
    • After SFT it did not work in the repo's runs:
      • GRPO after SFT reached 0.5% usage over 200 steps, 0% in the last 20;
      • the format score stayed about −0.18, the same as in every run (−0.19), so most answers never used the <think>/<answer> tags, even after SFT on tagged answers;
      • the likely cause: the gold data only ever showed [KEEP], and SFT loss never fell.

4. The reward-hacking story

  • The bug. The offline memory benchmark (SAMB) checked whether the gold tag string appeared anywhere in the output (a "bag of tags"), not whether it was attached to the right block.
    • Before the fix: an answer that simply lists all four tags plus the shielded words scored 1.0 on every metric (SAMB/samb_review_and_recommendation.md).
    • The same flaw was in GRPO: the +3 bonus paid for any tag, right or wrong.
  • The fix. Parse "block → directive" for each block and score per-class Macro-F1: the average F1 over the 4 directive types, so spamming one class doesn't pay.
    • After the fix (Gemma 4 31B, live, 156 samples): accuracy 24.9% (chance is 25%), Macro-F1 0.145.
    • 139 of 156 outputs gave the identical sequence KEEP, COMPRESS, EVICT, KEEP.
    • Note: that measurement was on the 31B model, not on the E4B models trained here.

6. Five likely questions

  1. "Why didn't more reward fix it?" GRPO learns from differences between the answers it samples. If no answer contains a directive, a bigger bonus multiplies zero. +1, +3 and +5 all stayed near 1%.
  2. "How did you pick group size?" G = 4 was chosen as "enough diversity for a relative advantage" within one H100 (training used about 23 GB). The repo has no sweep over G [NOT FOUND]. Too small a group is part of why rare behaviours never showed up.
  3. "How do you know it didn't forget other skills?" There was no separate forgetting benchmark [NOT FOUND]. A warning sign: after SFT the task reward fell (0.36 in Guardian, 0.21 after SFT). I'd add a held-out general benchmark before any further training.
  4. "What would you do next?"
    • Gold data with all four directives, balanced, and graded per block.
    • Check the SFT chat template and run longer, because the loss never fell.
    • Keep a "must" prompt for part of the batch while GRPO shapes the behaviour.
    • Reward the correct directive (Macro-F1), not any directive.
  5. "What surprised you most?" One word in the prompt ("may" → "must") did more than 5× the reward, a few-shot example, or higher temperature. Also, the evaluator could be gamed by listing every tag. I now check the grader before trusting a score.
